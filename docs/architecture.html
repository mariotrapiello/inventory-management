Factory Inventory Management System — Architecture

Full-stack demo: Vue 3 frontend, FastAPI backend, in-memory JSON mock data (no database)

Tech Stack

Frontend

Vue 3

  • Vue 3.4 (Composition API)
  • Vite 5 — dev server, port 3000
  • Vue Router 4 — client-side routing
  • Axios — HTTP client
Backend

FastAPI

  • FastAPI 0.110+
  • Uvicorn — ASGI server, port 8001
  • Pydantic 2.5+ — request/response validation
  • CORS open for local dev
Data & Testing

Mock Data + Pytest

  • JSON files in server/data/
  • Loaded into memory at startup, no persistence
  • Pytest + httpx TestClient, ~51 tests in tests/backend/

Data Flow — Example: Filtering Inventory by Warehouse

1

User interaction

User picks "London" in FilterBar.vue, bound via v-model to a shared ref.

2

Shared filter state

composables/useFilters.js exposes selectedLocation as a singleton ref — every component using useFilters() sees the update.

3

Watcher fires

Inventory.vue has a watch() on the filter refs that calls loadInventory().

4

API call

api.getInventory(filters) builds a query string, skipping any filter set to 'all', and calls GET /api/inventory?warehouse=London.

5

Backend filtering

main.py's apply_filters() filters the in-memory inventory_items list from mock_data.py down to matching rows.

6

Validation & serialization

FastAPI validates each row against the InventoryItem Pydantic model and serializes the list to JSON.

7

Re-render

The response updates inventory.value; a computed property re-applies the local search filter, and the table re-renders with London-only rows.
